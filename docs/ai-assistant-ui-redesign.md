# AI 英语教练 · 界面优化方案 v2

> 交付物：`ai-assistant-ui-v2.html`（可交互原型，含浅/深色、三档视口、优化前/后对比）
> 验证：`node scripts/ai-ui-smoke.mjs` → 31 项检查全部通过，运行期无 JS 报错
> 适用范围：`index.html` 第 528–539 行结构 / `css/ai-chat.css` / `js/ai-chat.js`

---

## 一、平台定位（明确结论）

**不是三套界面，是一套响应式 Web UI + 三个壳。** AI 助手的 DOM 完全由 `index.html` 渲染，三个平台共用同一份代码：

| 平台 | 承载方式 | 典型视口 | 需要单独处理的约束 |
|---|---|---|---|
| Web / PWA | 浏览器直开 | 1024–1920px | 宽屏三栏，hover 态可用 |
| Android | Capacitor 8.5 WebView | 360–430px | 状态栏/导航栏遮挡、`env(safe-area-inset-*)`、无 hover、系统返回手势 |
| 桌面 | Tauri 2.4 WebView | ≥1024px（窗口可窄至 900） | 无浏览器 UI，需自给标题栏留白 |

因此所有优化必须 **一次设计、三端生效**：断点统一、hover 态只作为增强（触屏有常驻替代）、安全区用 CSS 环境变量兜底。

**当前形态的关键判断**：AI 助手现在不是独立对话页，而是「AI 教练」页里的一张内嵌卡片（`.ai-chat-card`），消息区写死 `max-height: 360px` 内滚。这在桌面够用，在手机上等于把对话塞进一个 360px 的盒子里——**这是本次要改的第一件事**：把它升级为「对话工作区」，在宽屏用三栏、窄屏用全屏单栏。

## 二、核心功能区域梳理

### 现状（v1）

| 区域 | 实现 | 问题 |
|---|---|---|
| 对话窗口 | `.ai-chat-msgs`，定高 360px 内滚，`.ai-msg` 气泡 + 28px 头像 | 定高、无时间戳、无角色名、无消息级操作 |
| 输入框 | `#ai-chat-input` 单行 `input`，`maxlength=200`，Enter 发送 + 图标按钮 | 不能换行、200 字不够、无语音输入 |
| 快捷提问 | `.ai-chat-chips`，6 个 chip，随上下文切换 | 位置在消息区下方，输入后不变；窄屏换行挤压 |
| 历史记录 | `DataStore` 的 `ai_chat_history`，最多 50 条，**只恢复最近 2 条** | 无列表、无搜索、无删除、无「新对话」 |
| 设置面板 | **不存在**，LLM/语音/语速散落在全局设置页 `#page-settings` | 对话中改设置要跳页，路径断 |
| 状态 | `.ai-status-badge`（在线增强 / 离线模式） | 信息正确，但移动端被挤出可视区 |
| 跳转 | `[跳转:xxx]` → `.ai-goto` 小号「前往」文字按钮 | 视觉权重不足以承担行动号召 |

### 优化后（v2）

对话工作区拆为 **6 个功能区**：历史栏、消息流、输入区、上下文栏、设置抽屉、状态标识。

## 三、痛点诊断（含实测数据）

### A. 消息可读性差

| # | 痛点 | 证据 |
|---|---|---|
| A1 | 回复是 `innerHTML` 拼的纯文本，靠 `<br>` + `·` 分行，**完全没有结构** | `js/ai-chat.js` 的 `_welcome()` / `_explainWord()` 直接拼 `'<br>· '` |
| A2 | 中英混排无区分：单词、音标、中文释义、例句同一字号同一色 | `.ai-msg-bubble` 只设了 `font-size: var(--text-sm)` |
| A3 | 例句淹没在文本里，**不能单独朗读**；英语学习场景下这是高频刚需 | 现有只有 `data-speak` 全局委托，气泡内无入口 |
| A4 | 无时间戳、无角色名；刷新后靠一行「—— 以上是上次的对话 ——」分隔 | `.ai-hist-sep` |
| A5 | 长回复（7 天计划、发音诊断）挤在 360px 定高的滚动区里，要来回拖 | 无长内容策略 |
| A6 | **用户气泡对比度不达标**：`--sage #5B82A6` + 白字 = **4.05:1**，低于 WCAG AA 正文 4.5:1 | 实测计算 |
| A7 | **深色模式下用户气泡严重不达标**：深色 `--sage` 翻成 `#7BA9CE`，白字仅 **2.50:1** | 实测计算 |
| A8 | **令牌误用**：`color: var(--text-base)` —— 但 `--text-base` 在 `design-system.css:89` 定义的是 `1rem`（字号），不是颜色。该写法在 `ai-chat.css` 60/174/198、`dashboard.css:215`、`nav.css:199` 共 5 处，实际都**静默降级为继承色** | 已核实 |

### B. 操作路径过长

| # | 痛点 | 现状 |
|---|---|---|
| B1 | 「清空对话」是标题右侧一个 11px 小按钮，无二次确认 | `.ai-clear-chat` |
| B2 | 历史只有最近 2 条恢复，想找回上周的对话做不到 | `_welcome()` 里 `history.slice(-2)` |
| B3 | 助手设置在全局设置页，对话中想关闭 LLM 增强要跳出当前页 | 无就近设置 |
| B4 | 输入框单行、200 字上限、**无语音输入**（英语学习软件的硬伤） | `maxlength="200"` |
| B5 | 回复里推荐动作渲染成小号文字按钮，用户视而不见 | `.ai-reply-btn` / `.ai-goto` |
| B6 | 快捷 chip 固定 6 个，与当前回答的上下文脱节 | `_refreshChips()` |

### C. 视觉与维护

| # | 痛点 |
|---|---|
| C1 | `.ai-clear-chat` 在 `ai-chat.css` 里**重复定义了两遍**（286–305 与 307–326 行完全一致） |
| C2 | 气泡同时用 1px 边框 + `shadow-xs`，描边过重、层级扁平 |
| C3 | 深色模式下 AI 组件未做专项适配，只靠父级令牌兜底 |

## 四、优化方案

### 4.1 信息架构：内嵌卡片 → 对话工作区

```
┌──────────┬──────────────────────────┬────────────┐
│ 历史栏    │  消息流                   │ 上下文栏    │  ≥1280 三栏
│ 248px    │  flex 自适应高度           │ 288px      │
├──────────┴──────────────────────────┤            │
│  输入区（sticky，安全区兜底）          │            │
└─────────────────────────────────────┴────────────┘
     1024–1279 两栏（隐上下文栏） · <1024 单栏 + 历史抽屉
```

消息区从「定高 360px」改为 `flex:1; min-height:0; overflow-y:auto`，高度随容器自适应——这是解决 A5 的前提。

### 4.2 配色方案（沿用品牌，补齐语义层级）

保留品牌 sage 蓝灰 + coral 橙，新增三级表面层级与深色专项映射。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--canvas` | `#F4F6F9` | `#0E141B` | 页面画布 |
| `--surface-0` | `#FFFFFF` | `#151D27` | 卡片、输入区 |
| `--surface-1` | `#F7F9FB` | `#1C2531` | AI 气泡、hover |
| `--surface-2` | `#EEF4F9` | `#22303F` | 例句卡、选中态 |
| `--line` | `#DCE2EA` | `#2A3746` | 默认描边 |
| `--brand-500` | `#5B82A6` | `#7BA9CE` | 主色（保持品牌不变） |
| `--brand-600` | `#4A6F93` | `#5E8FB8` | hover / 用户气泡 |
| `--brand-700` | `#3E5F7F` | `#BBD7EC` | 强调文字、例句关键词 |
| `--accent-500` | `#FF8A65` | `#FF9A76` | **仅**用于需要行动/提醒 |
| `--text-1` | `#1F2933` | `#E7EDF4` | 正文 |
| `--text-2` | `#5A6B7C` | `#A6B4C3` | 次级 |
| `--text-3` | `#8A98A6` | `#7C8B9B` | 元信息（非关键） |

**对比度实测（已按 WCAG 2.1 相对亮度计算）**

| 组合 | 比值 | 判定 |
|---|---|---|
| 正文 `#1F2933` / `#FFFFFF` | 14.1:1 | ✅ AAA |
| 次级 `#5A6B7C` / `#F7F9FB` | 5.19:1 | ✅ AA |
| 用户气泡 白字 / `#4A6F93` | 5.27:1 | ✅ AA（修复 A6，原 4.05:1） |
| 深色用户气泡 `#0E141B` / `#5E8FB8` | 5.37:1 | ✅ AA（修复 A7，原 2.50:1） |
| 深色正文 `#E7EDF4` / `#151D27` | 14.4:1 | ✅ AAA |
| 深色次级 `#A6B4C3` / `#151D27` | 8.04:1 | ✅ AAA |

> **必须修**：A8 的 5 处 `color: var(--text-base)` 改为 `var(--text-1)`（或新增 `--text-body` 颜色令牌），并单独新增字号令牌，避免颜色/字号令牌同名。

### 4.3 间距系统（4px 基线）

| 令牌 | 值 | 用在 |
|---|---|---|
| `--sp-1` | 4px | 图标与文字间隙 |
| `--sp-2` | 8px | chip 间距、气泡内元素间隙 |
| `--sp-3` | 12px | 气泡内边距（窄屏）、卡片内元素 |
| `--sp-4` | 16px | **消息之间的垂直间距**、气泡内边距 |
| `--sp-5` | 20px | 卡片外边距 |
| `--sp-6` | 24px | 消息区上下留白 |

关键决策：**消息间距从 10px 提到 16px**（移动端 12px）。10px 在多轮对话里会让气泡连成一片，是 A1 的帮凶。

### 4.4 字体层级

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 | 20px / 1.35 | 600 | 「AI 英语教练」 |
| 回答结论 | 18px / 1.55 | 500 | AnswerCard 首行（单词 + 音标 + 词性） |
| **例句英文** | **16px / 1.6** | 400 | 例句卡主行，单独字号 |
| 正文 | 15px / 1.75 | 400 | 释义、说明 |
| 例句中文 / UI | 13–14px / 1.5 | 400 | 次级信息、按钮 |
| 元信息 | 12px / 1.4 | 400 | 时间、分区标题 |

**中英分离**是 A2 的正解：英文片段加 `lang="en"` 并套 `--font-en`（Inter 优先），中文走 PingFang / 微软雅黑；英文 16px、中文 13px 双层排布，扫读路径从「一坨字」变成「先看英文、再看中文」。

### 4.5 响应式适配

| 断点 | 布局 | 关键变化 |
|---|---|---|
| ≥1280px | 三栏 248 / 自适应 / 288 | 上下文栏常驻；hover 浮出消息操作 |
| 1024–1279px | 两栏 248 / 自适应 | 收起上下文栏 |
| 768–1023px | 单栏 + 历史抽屉 | 历史栏变 `position:fixed` 侧滑，遮罩关闭 |
| <768px | 全屏单栏 | 头像 32→28px、消息间距 16→12px、**消息操作常驻**（触屏无 hover）、发送键 40→44px、输入区 `padding-bottom` 加 `env(safe-area-inset-bottom)` |
| <400px | 紧凑 | 例句卡降 padding，统计卡单列 |

消息正文限制 `max-width: min(640px, 100%)`，保证行长 ≤ 约 68 字符——长行是中文长文可读性差的主因之一。

### 4.6 交互流畅性

- **动效**：统一 `cubic-bezier(.16,1,.3,1)`；入场 320ms、hover 200ms、焦点环 120ms。消息入场 `translateY(8px) → 0` + 淡入；打字指示器三点 1.1s 循环。
- **反馈**：发送后立即出现「正在输入」占位（消除等待焦虑）；复制/朗读/toast 即时反馈；点击例句朗读按钮有 `scale(1.06)` 微反馈。
- **新消息定位策略**（本次实测后确立）：回答整体放得下 → 贴底；放不下 → 把**回答顶部对齐可视区顶**，保证 18px 的结论行第一眼可见。若一律贴底，用户进来的第一眼是回答结尾，等于把最重要的信息藏了。
- **「回到最新」按钮**：仅在用户真实滚动（wheel / touchstart / keydown / mousedown）之后出现。不用时间窗口区分程序滚动——实测该判据在快机器与虚拟时间下会失效，导致按钮在首屏误弹。
- **路径缩短**：回答底部的行动按钮把「下一步」从文字里捞出来，一次点击完成追问；历史/设置就近化，不用跳页。
- **减少动效**：`prefers-reduced-motion: reduce` 下全部动效降为 0.01ms。

### 4.7 无障碍（WCAG AA）

- 消息列表 `role="log"` + `aria-live="polite"` + `aria-relevant="additions"`，新消息自动播报
- 所有图标按钮带 `aria-label`；开关用 `role="switch"` + `aria-checked`
- 抽屉 `role="dialog"` + `aria-modal` + Esc 关闭 + 遮罩点击关闭
- **禁止嵌套交互元素**：历史项曾把删除按钮放进 `<button>` 内（已在原型中修正为「容器 div + 两个并列 button」）
- 触屏命中区 ≥44px；`:focus-visible` 统一 3px 焦点环
- 对比度全部 ≥4.5:1（见 4.2 实测表）

| 痛点 | 方案 | 原型对应 |

| B5 行动号召弱 | `.ai-reply-btn` 文字按钮 → 带图标的 pill 行动按钮，主次两级 | `.act` / `.act.primary` |
| B6 chip 脱节 | chip 固定在输入区上方，随上下文刷新，窄屏横向滚动 | `.chips` |
| C1 重复样式 | 删除重复的 `.ai-clear-chat` 定义 | —（需改源码） |

### 6.2 关键组件规格

| 组件 | 尺寸 / 间距 | 状态 |
|---|---|---|
| `AnswerCard` | 段间距 16px；结论 18px；例句卡 padding 12/16 | 默认 |
| `ExampleCard` | 英文 16px/1.6，中文 13px；朗读按钮 32px（触屏 36px） | hover 边框加深 + `translateX(2px)`，朗读按钮 hover 反色放大 |
| `MessageActions` | 三个 12px 文字按钮，pt 4px | 桌面 hover/focus 浮出；触屏常驻 |
| `Composer` | textarea 40→132px 自适应；发送键 40px（触屏 44px） | 空内容时发送键 disabled；聚焦时 3px 焦点环 |
| `SuggestionChip` | 高 28px（触屏 34px），pill，横向滚动隐藏滚动条 | hover 转品牌色 |

## 九、原型实测复盘（真机渲染踩到的坑）

原型不是画完就交，而是用 **真 Chromium 在 1440 / 500 / 390 三档视口 + 浅深色 + 优化前后** 逐张截图核对，期间修掉了 4 个只有真渲染才暴露的问题：

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 3 条例句的回答被折叠，只露出 1 条半 | 折叠阈值写死 560px，窄屏下英文换行多、内容更高，正常回答也超阈值 | **砍掉气泡内折叠**。消息区已是全高滚动容器，再折一层是双重滚动 |
| 2 | 深色/长回答下消息区整片空白（滚动位置其实正确） | `mask-image` 作用在滚动容器上，与滚动合成层冲突导致错位 | 顶部渐隐改用 `.conv-body::before` **覆盖层渐变**，不再 mask 滚动容器 |
| 3 | 首屏就弹出「回到最新」 | 用 `setTimeout` 时间窗口区分程序/用户滚动，在快机器与虚拟时间下失效 | 改为**基于用户输入事件**（wheel/touchstart/keydown/mousedown）的确定性判据 |
| 4 | 历史项删除按钮嵌在 `<button>` 内 | 嵌套可交互元素，键盘与屏幕阅读器行为未定义 | 改为「容器 div + 标题 button + 删除 button」并列结构，并纳入冒烟测试断言 |

同时确立两条与直觉相反但实测更优的规则：**滚动容器不要用 `scroll-behavior:smooth`**（会让「连续微调 scrollTop」变成动画叠加）；**长回答定位到顶部而非底部**（结论行优先）。

回归方式：`node scripts/ai-ui-smoke.mjs`，34 项断言覆盖结构渲染、输入发送、快捷提问、行动按钮追问、历史切换、设置抽屉、主题切换、优化前后对比、视口切换、无障碍约束，全部通过且运行期零 JS 报错。
